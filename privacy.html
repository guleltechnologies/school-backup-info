School Backup privacy policy

Last updated: 6 November 2026

This policy describes the School Backup Google Drive integration operated by Gulel Technologies. It covers the backup utility and this information website; it does not replace the school's privacy notices for its application and records.

Purpose and authorized users

The utility stores encrypted school application backups for disaster recovery and allows authorized operators to verify, restore and make independent encrypted copies of them. Only the designated backup account owner authorizes Google access. It is not a Google sign-in service for students, parents or staff.

Google data and permissions

The integration requests the Google Drive drive.file scope. It uses the Drive API to create, list, read, update and delete repository files created through this application, including their names, identifiers, sizes and other file metadata needed to operate the repository. It also checks account storage quota to detect insufficient backup space.

It does not request Gmail, Google Photos, contacts, or broad access to unrelated Drive files. OAuth authorization and refresh tokens allow the utility to continue operating without asking for the account password. The utility does not collect or store the Google account password.

Storage and protection

Database and application-file snapshots are encrypted by restic before transfer to Google Drive. Authorized operators with the repository password can decrypt recovery copies. Google hosts the encrypted repository; access to the Drive account alone does not provide the backup decryption password.

Protected operator systems store OAuth credentials and the repository password separately from the public website and application images. Plaintext database dumps and media may exist temporarily in private staging and recovery directories on operator-controlled systems. Operators must protect and clean up those directories. Encryption does not prevent deletion by someone who has sufficient account or repository permissions.

Use and sharing

Google user data is used only to operate, protect and recover these backups. We do not sell it, use it for advertising, or use it to train artificial-intelligence models. Authorized recovery operators may access backup contents for school-approved recovery work. Google processes hosted data under its own service terms and privacy policy.

School Backup's use of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

Retention and deletion

The planned automatic retention policy keeps seven daily and four weekly restore points, which can overlap. Cleanup is enabled only after recovery testing. Failed cleanup or disabled automation can leave older snapshots. Independent encrypted local copies have separate operator-managed retention.

Deleting a record in the school application does not immediately remove it from existing recovery snapshots. Contact the operator for an appropriate deletion process across active data, retained snapshots and independent copies. Repository chunks are shared between snapshots: individual Drive repository files must not be deleted manually as a substitute for a reviewed retention or complete-repository deletion process.

Revoke Google access

The account owner can revoke the application's access through Google Account third-party connections. Revocation stops future authorized Drive operations; it does not automatically delete existing Drive backups, local copies or operator-held credentials. The operator can remove retained credentials and review deletion of the repository and local copies when discontinuing the service.

This information website

These static pages contain no account sign-in, backup upload form, advertising, analytics scripts or application cookies. If hosted on GitHub Pages, GitHub processes visitor connection information, including IP addresses, according to the GitHub Privacy Statement. No backup data or OAuth credentials are published on these pages.

Contact and changes

For questions, support or deletion requests, contact Gulel Technologies through the user support email displayed on the application's Google authorization screen. Material changes to Google data access or use will be reflected in this policy, with renewed authorization where required.
